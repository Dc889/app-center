## 2. 标准发版流程（6 步闭环）

### 第 1 步：本地修改代码与影响评估

1. 确认当前处于 `main` 分支且工作区干净：
   ```powershell
   Set-Location "c:\Users\dc948\Project\11-AIAPPCENTER\app-center"
   git status
   git pull --rebase origin main
   ```
2. 完成代码修改，并记录本次涉及的文件清单及对应需重建的容器服务（见 1.1 节对照表）。
3. **离线构建红线**：修改 `docker/Dockerfile.*` 时，**严禁新增 `apk add` / `apt-get` / 在线 `npm install` 新依赖**，`192.168.0.7` 为纯离线内网环境，无外网 DNS 解析，会导致镜像构建失败。

---

### 第 2 步：本地编译与语法校验（必做）

推送与部署前，必须在本地通过 TypeScript 类型检查、Vite 打包及 Node.js 后端语法校验：

```powershell
Set-Location "c:\Users\dc948\Project\11-AIAPPCENTER\app-center"

# 1. 前端 TypeScript 校验 + Vite 生产构建（必须 0 报错）
npm.cmd run build

# 2. 对本次修改的后端 .mjs 文件执行语法检查（示例）
git diff --name-only -- '*.mjs' | ForEach-Object {
  node --check $_
  if ($LASTEXITCODE -ne 0) { throw "Syntax error in $_" }
}
```

> **提示**：PowerShell 5.1 中不要使用 `&&` 连接命令，请使用分号 `;` 或 `if ($LASTEXITCODE -eq 0)` 判断退出码。

---

### 第 3 步：提交并推送到 Git 仓库

确保仅暂存本次改动相关的源码文件（避免误提交临时日志或无关未跟踪文件）：

```powershell
Set-Location "c:\Users\dc948\Project\11-AIAPPCENTER\app-center"

# 查看改动概览
git status --short
git diff --stat

# 按需暂存并提交（遵循 Conventional Commits 规范）
git add management/ capability/
git commit -m "fix(<模块>): <简明描述本次修复或变更>"

# 推送至远程 main 分支
git push origin main
```

### 第 4 步：同步代码文件到 `192.168.0.7`

由于 `192.168.0.7` 处于离线内网，无法直接 `git pull` GitHub，因此采用 **增量 SFTP / SCP 上传** 方式将本次提交的变更文件同步到 `/data/app-center/app-center/`。

#### 方式 A：使用 `scp`（已配置 SSH 免密登录时推荐）

```powershell
Set-Location "c:\Users\dc948\Project\11-AIAPPCENTER\app-center"

# 自动读取最近一次 Git 提交修改的文件并逐个上传
$files = git diff-tree --no-commit-id --name-only -r HEAD
foreach ($rel in $files) {
  if (Test-Path $rel) {
    scp $rel "root@192.168.0.7:/data/app-center/app-center/$rel"
  }
}
```

#### 方式 B：使用 Python `paramiko` 脚本增量上传（支持通过环境变量传密码）

```powershell
# 先在当前终端设置临时环境变量（勿将密码写入代码或文档）
$env:DEPLOY_SSH_PASS = "<服务器root密码>"

@'
import os, subprocess, paramiko

local_root = r"c:\Users\dc948\Project\11-AIAPPCENTER\app-center"
remote_root = "/data/app-center/app-center"

# 自动获取最近一次 commit 的所有变更文件
out = subprocess.check_output(
    ["git", "diff-tree", "--no-commit-id", "--name-only", "-r", "HEAD"],
    cwd=local_root, text=True
)
files = [line.strip() for line in out.splitlines() if line.strip() and not line.startswith("docs/")]

ssh = paramiko.SSHClient()
ssh.set_missing_host_key_policy(paramiko.AutoAddPolicy())
ssh.connect("192.168.0.7", username="root", password=os.environ["DEPLOY_SSH_PASS"], timeout=15)
sftp = ssh.open_sftp()

for rel in files:
    lp = os.path.join(local_root, rel.replace("/", os.sep))
    if not os.path.exists(lp):
        continue
    rp = f"{remote_root}/{rel}"
    # 确保远端父目录存在
    rdir = os.path.dirname(rp)
    ssh.exec_command(f"mkdir -p '{rdir}'")
    sftp.put(lp, rp)
    print("Uploaded:", rel)

sftp.close()
ssh.close()
'@ | python -
```

### 第 5 步：在 `192.168.0.7` 上重建容器并挂载 Dify 网络（关键！）

登录 `192.168.0.7` 执行 Docker Compose 按需重建。

> **⚠️ 极其关键（必做）**：每次 `docker compose up -d --build` 重建 `app-center-management` 或 `app-center-executor` 后，Docker 会重置容器的网络连接，**必须重新执行 `docker network connect docker_default`**，否则管理端将无法连接 Dify PostgreSQL（`docker-db-1`）、Nginx 访问日志（`docker-nginx-1`）和 Plugin Daemon（`docker-plugin_daemon-1`）。

```bash
# 1. 进入 docker compose 目录
cd /data/app-center/app-center/docker

# 2. 按本次改动范围重建对应服务（示例：同时重建 management、web、executor）
docker compose up -d --build --no-deps management web executor

# 3. 重新挂载 Dify 的 docker_default 网络（幂等，已挂载则忽略）
docker network connect docker_default app-center-management 2>/dev/null || true
docker network connect docker_default app-center-executor 2>/dev/null || true

# 4. 等待容器变为 healthy 并查看状态
sleep 5
docker ps --filter name=app-center --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

#### 按需重建速查

| 改动场景 | 重建命令 |
| :--- | :--- |
| 仅修改前端（`.tsx` / `.css`） | `docker compose up -d --build --no-deps web` |
| 仅修改管理端后端（`management/**/server/*.mjs`） | `docker compose up -d --build --no-deps management && docker network connect docker_default app-center-management 2>/dev/null \|\| true` |
| 仅修改执行器（`capability/modules/**`） | `docker compose up -d --build --no-deps executor && docker network connect docker_default app-center-executor 2>/dev/null \|\| true` |
| 前后端 + 执行器联动修改 | `docker compose up -d --build --no-deps management web executor && docker network connect docker_default app-center-management 2>/dev/null \|\| true && docker network connect docker_default app-center-executor 2>/dev/null \|\| true` |

### 第 6 步：线上健康检查与回归验证

容器全部显示 `Up ... (healthy)` 后，执行以下快速验证：

1. **检查容器运行日志无启动异常**：
   ```bash
   docker logs --tail 50 app-center-management
   docker logs --tail 50 app-center-executor
   ```
2. **验证网络连通性**（确保 `app-center-management` 已正确接入 `docker_default`）：
   ```bash
   docker inspect app-center-management --format '{{json .NetworkSettings.Networks}}' | grep docker_default
   ```
3. **验证 HTTP 服务与登录接口**：
   ```bash
   curl -I http://192.168.0.7:8088/
   ```
4. **浏览器端业务回归**：
   - 打开 `http://192.168.0.7:8088`（建议 `Ctrl+Shift+R` 强刷缓存）。
   - 使用对应角色账号（如管理员 `li.qiang`、运营 `zhou.min`、租户 `tenant01@kpw.com` / `tenant02@kpw.com`）复测本次修复的核心页面与工单流转。

## 3. 常见问题与避坑清单

1. **容器重建后 Dify 数据（知识库/智能体/模型监控）全部报连接超时或空数据**
   - **原因**：重建容器后忘记重新挂载 `docker_default` 网络。
   - **解决**：立即执行 `docker network connect docker_default app-center-management` 和 `docker network connect docker_default app-center-executor`。
2. **`docker compose build` 卡住或报 `temporary error (try again later)` / DNS 解析失败**
   - **原因**：`192.168.0.7` 无外网访问，触发了未缓存的 `apk add` 或 `npm ci`。
   - **解决**：不要修改 `Dockerfile.*` 中 `deps` 阶段之前的指令（保持 `package.json` / `package-lock.json` 与基础镜像层命中本地缓存），也不要新增任何联网安装步骤。
3. **前端页面出现内网 Docker 主机名（如 `http://docker-nginx-1/...`）**
   - **原因**：后端直接透传了容器内部环境变量 `DIFY_API_BASE` 给前端用于浏览器跳转。
   - **解决**：返回给前端浏览器打开的链接必须过滤内网容器主机名（`docker-nginx-1`、`host.docker.internal`、`127.0.0.1`），由前端基于 `window.location.hostname` 或显式配置的公网/内网可访问地址 `DIFY_PUBLIC_BASE` 拼接。
4. **修改了文件但容器里未生效**
   - **原因**：只上传了文件但忘记 `--build`，或只重建了 `management` 忘记重建 `executor` / `web`。
   - **解决**：对照 1.1 节目录映射表，确保带上 `--build` 参数重建对应服务。

## 4. 紧急回滚流程

若发版后发现严重问题，可按以下方式快速回滚：

1. **本地回退 Git 提交**：
   ```powershell
   Set-Location "c:\Users\dc948\Project\11-AIAPPCENTER\app-center"
   git log -n 5 --oneline
   git revert <问题commit的hash>
   git push origin main
   ```
2. **重新执行第 4 步（上传回退后的文件）与第 5 步（重建容器 + 挂载 `docker_default` 网络）**，约 30 秒内即可恢复线上服务。
