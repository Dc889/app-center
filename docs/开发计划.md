# 应用中心开发计划

依据 `app-center/docs/app-center-design.md` 第 13 节。三层结构和四个仓库的边界以那一节为准，本文件只规定先做哪一段、做完怎么算。

当前会话不能切换 Cursor 的 Plan 模式。Plan 模式要在对话输入框里由使用人打开。后续开发按本文件的阶段顺序做。

## 已经有的

前端演示在 `app-center/src/App.tsx`，不推倒。导航、三种角色、智能体仓库主体、手工申请的通用抬头已经能看。AG-01 到 AG-05、PLG-03、MCP-02、SKL-03 有各自的字段。其余工单还是来源加资源的通用壳。阶段 0 的契约已经写在下面。阶段 1 的 Skill 下载已由 `server/execute.ts` 执行：陈宇下载公文摘要会写流水，周敏下载表格分析会因组织不符失败。阶段 2 的插件安装已接到 Dify 本地包接口；没有控制台地址或登录凭证时写执行失败。MCP、智能体还没有服务，也还没有 Docker 部署。

## 阶段怎么推进

一个阶段验收通过，才开始下一个服务。补页面可以跟在对应服务后面做，不用等全部页面完成才做容器。不改 RAGFlow、Dify 的源码和数据库。未要求时不提交 git。

## 阶段 0：写下契约

写出三份记录的字段，先放在文档里，不接真实产品：

- 工单执行请求：工单号、工单类型、动作、资源标识、目标账户。
- 执行结果：成功或失败、失败原因、结果标识。某个版本没有对应 API 时，结果写执行失败，并写明无法自动执行。
- 目录记录：名称、状态、可见范围、来源标识。Skill 多文件地址和版本，插件多已批准版本，MCP 多 URL 指纹，智能体多三种使用方式。

同时核对 Skill 下载不调用 Dify 或 RAGFlow。Skill 文件放在本平台对象存储。

做完的标志：契约写在本文件下面的「契约」一节，并且写明 Skill 下载不依赖 Dify、RAGFlow。

## 阶段 1：Skill 最小闭环

先做 Skill 服务和一条下载闭环。服务保存文件、版本和下载流水，文件放对象存储，不运行 Skill。可以用一个进程先把契约跑通，跑通后再放进 Docker。

闭环路径：陈宇在手工申请提交 SKL-03，管理系统把执行请求交给能力组件，能力组件向 Skill 服务取文件并写下载流水，结果写回这张工单。

做完的标志：浏览器里陈宇能走完这一条，工单上能看到成功或失败。这一步不安装插件，不绑定 MCP，不发布智能体。

## 阶段 2：插件包服务

插件服务只保存内网安装包、扫描结果和已批准版本。不自建插件运行时，不访问 GitHub 和公网市场。安装、升级、卸载由能力组件调用 Dify 现有接口。接口不存在就让工单执行失败。

先打通 PLG-03 的公开安装。分享给他人的审批仍留在管理系统。

做完的标志：一条安装工单能把结果写回。仓库页上的安装次数、筛选和卸载可以在这条通了之后再补。

## 阶段 3：MCP 目录服务

MCP 服务只保存目录、URL 指纹，以及正常、隔离、下架。地址来自内网模型中心，申请单不手填。绑定和解绑由能力组件使用获批用户已经登记的 Dify 调用身份。真正的 MCP 进程不放进这个容器。

先打通 MCP-02 的范围内绑定。

做完的标志：一条绑定工单能把结果写回，页面不出现可编辑的地址栏。

## 阶段 4：智能体目录服务

智能体服务只保存已生效的发布目录、可见范围，以及运行、嵌入网站、访问 API。应用仍在 Dify 运行。这个容器不是第二个智能体运行时。

先打通 AG-02：审批通过后，目录里出现这条应用，三种使用方式按工单写入。

做完的标志：周敏办完一张发布单后，陈宇在范围内能在仓库里看到该应用。未生效的应用不进仓库。

## 可以穿插、但不挡住上面四个服务

这些按设计第 6、7、8 节补，缺了也不阻止当前阶段的闭环：

- 其余工单仍是通用壳的，按第 6 节补字段。
- 仓库里的安装、绑定、下载写入我的申请。
- 插件、MCP、Skill 仓库页上还缺的数字、筛选和列。
- 还在共用缩略页的监控页拆开。

## 契约

Skill 下载不调用 Dify，也不调用 RAGFlow。文件放在本平台对象存储 `app-center/server/skill-objects`。下载流水写在 `app-center/server/data/downloads.json`。只有能力组件读取这两处。管理系统只提交下面的执行请求。执行代码在 `app-center/server/execute.ts`。

工单执行请求：

| 字段 | 含义 |
| --- | --- |
| ticketNo | 工单号 |
| ticketType | 工单类型，目前只执行 `SKL-03` |
| action | 动作，Skill 下载为 `download` |
| resourceId | 资源名称 |
| account | 目标账户 |
| org | 目标账户的组织 |

执行结果：

| 字段 | 含义 |
| --- | --- |
| ok | 成功为 true，失败为 false |
| failureReason | 失败原因。类型未接入或没有对应 API 时写「无法自动执行」 |
| resultId | 成功时的下载流水号，失败时为空 |
| version | 成功时的版本号 |
| sha256 | 成功时的文件摘要 |

目录记录：

| 字段 | 含义 |
| --- | --- |
| name | 名称 |
| status | 可下载或已下架 |
| orgs | 可见组织。空数组表示全网段 |
| sourceId | 来源标识 |
| version | Skill 版本 |
| file | 对象存储中的文件名 |

插件安装已核对 Dify 现有接口，只使用本地包，不使用 GitHub 或公网市场。上传是 `POST /console/api/workspaces/current/plugin/upload/pkg`，安装是 `POST /console/api/workspaces/current/plugin/install/pkg`。调用需要环境变量 `DIFY_API_BASE` 和 `DIFY_CONSOLE_TOKEN`。两者缺一，工单写「无法自动执行：Dify 控制台地址或登录凭证未配置」。MCP 以后补 URL 指纹。智能体以后补运行、嵌入网站、访问 API。这两项现在不执行。
