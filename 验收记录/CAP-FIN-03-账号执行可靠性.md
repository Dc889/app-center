# CAP-FIN-03：账号执行可靠性与原生协议核对

2026-11-20。本次完成账号执行防护与只读协议核对；**不新增 ACC 真机执行通过项**。原子清单 **52/59**、部署分支 **23/35**、整单 **0/27**。具体事实见 [脱敏记录](CAP-FIN-03-账号执行可靠性.json)。

## 本次修复

- 人员从管理端可信目录按稳定 ID 获取，不接受调用方账户名提示代替。产品 UUID 丢失不退回同名新账户，缺少人员映射的同名账户不自动接管；重复人员映射和冲突 UUID 拒绝。
- Dify 读写前 GET 核对凭证当前真实工作区，不能以查询参数伪装归属。未知账户名、可用状态或权限不生成恢复基线；显示名、昵称、登录邮箱分别保留，显式 UUID 映射只标识人员，不制造当前产品账户名。所有者角色不冒充可无损恢复的管理员角色。
- 拒绝 HTTP 200 内的业务错误、不完整用户清单、重复 ID 和非 JSON。审批修订必须唯一、非负且为安全整数。请求有界超时，错误不转发原始上游正文或凭证。
- 管理端按执行冻结审批产品基线，包括历史重试；能力端写前重读并比对，缺失或变化则停止。首个产品写之前持久化 `reconciling` 和逐步写入意图，重启不自动重放。
- 两端写后重新读取 ID、工作区、名称、启停与权限，结果不符不提交平台。明确拒绝后的补偿只还原本次字段；写入超时/5xx/断连/无法解析均保留未知，禁止仅因当前读回旧值而自动回滚或封存解锁。
- 平台最终提交响应丢失时保留 `reconciling`，不回滚产品。新增同路径 GET 原始提交证明，服务鉴权、只读、不增加修订；重启核对原执行、请求映射、身份修订及产品现状后完成本地记录，不重新写产品或 PUT 身份。
- 一致性查证无法读取产品时返回 503，不填造空账户；已提交或提交待查证时拒绝回滚解锁证明。产品阶段中断但缺乏终态证明的执行继续保留限制，不宣称已恢复。
