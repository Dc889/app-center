# 能力组件结构与多人分工

更新于2026-11-20。代码目录是`capability/`；`GET /internal/v1/capabilities`是能力查询接口。此次重构将登记与执行解耦为公共框架和按功能归属的模块，部署仍为现有单体执行服务及四个仓库服务。

## 已落地结构

```text
capability/
  app/
    service.mjs                 # 启动装配
    modules.mjs                 # 唯一模块组合表，公共维护者负责
    tests/
  platform/
    registry/                   # 描述符校验、动作索引、部署证据及能力查询
    execution/                  # 接单、幂等、执行持久化、查询、公共读取路由
    dify/                       # 共用连接配置
    catalog/                    # 仓库通用只读基础
  modules/
    agents/ keys/ plugins/ skills/ knowledge/ mcp/
    accounts/ tools/ events/ integrations/ observability/
      public.mjs                # 唯一跨模块入口与capabilityModule
      handlers/                 # 本领域动作执行
      adapters/                 # 本领域产品协议
      queries/                  # 候选、目录、快照与读取
      tests/                    # 本模块测试，空目录不算验收
      README.md
  repositories/
    skill/ plugin/ mcp/ agent/   # 现有独立仓库，各有public.mjs
  executor/service.mjs          # 原启动路径兼容转发，无业务实现
  adapters/*.mjs                # 原适配器路径兼容转发，无新增业务
```

## 分工归属

以下是角色槽位，派工时填写实际姓名/Git账号。同一人可以兼任多个角色，同一个目录只有一位主维护者。CODEOWNERS中的capability-*账号是待替换的占位值，不代表已设置有效GitHub审批。

| 角色 | 独占目录 | 交付范围 |
| --- | --- | --- |
| 能力公共负责人 | app、platform、executor兼容入口、adapters兼容入口、dev中的能力门禁及公共测试 | 接单/持久化/幂等/查证公共协议、模块组合、证据核验；不能替业务模块增加产品成功假设 |
| 智能体开发 | modules/agents；repositories/agent | AG-01~05、目录/候选/版本/影响与替代、`application-targets`列表与详情、智能体运行相关适配 |
| 密钥开发 | modules/keys | KEY-01/02、登记和一次性领取(`/key-registrations/:registrationId/reveal`)、真实创建/撤销/轮换查证 |
| 插件开发 | modules/plugins；repositories/plugin | PLG-01~04、安装/升级/卸载、禁用恢复、`/intake/plugin/:intakeId`上传扫描及实例读取 |
| Skill开发 | modules/skills；repositories/skill | SKL-01~04、交付与结算、取消/关闭证据、`/intake/skill/:intakeId`上传扫描及目录版本 |
| 知识库开发 | modules/knowledge | KB-01~05，Dify/RAGFlow协议分别放本模块adapters子目录，三种绑定实现独立验收 |
| MCP开发 | modules/mcp；repositories/mcp | MCP-01~03、目录/绑定(`/binding-contexts/:resourceId`)/隔离/下架与provider映射 |
| 账号开发 | modules/accounts | ACC-01/02、两端账号变更、补偿/查证(`/executions/:executionId/account-consistency`)与封存证明 |
| 工具开发 | modules/tools | TOL-01技术定义、批准登记与撤销 |
| 事件关联开发 | modules/events | 为EVT关联提供能力侧证据；EVT-01动作仍为空，不新增事件直接执行 |
| 集成读取开发 | modules/integrations | 工作区(`/workspaces`)、模型资源来源、产品目录身份映射 |
| 观测开发 | modules/observability | observations/inventory/overview-summary等真实采集与快照，不从安装量推算调用量 |

两人开发时可采用：A兼公共负责人以及agents/keys/accounts/tools/integrations/observability，B负责knowledge/plugins/skills/mcp/events；仓库按对应领域同一人维护。跨服务契约由提供方与管理端负责人共同评审，不把所有人安排修改app/service.mjs。

## 模块登记契约

`public.mjs`导出`capabilityModule={id,actions,resources,catalogs,routes,reconcile?,init?}`。id在整个服务内唯一。

- actions每项为`{ticketType,ticketTypeVersion,action,variants,execute?,ready?,validatePayload?,reconcile?,cancel?,retryOnServerError?}`。同一类型/版本/动作只有一个拥有者；动作必须属于actions.json，契约中的每个动作必须有明确拥有者，未实现也必须显式登记。variants非空且唯一，无分支填null；KB-03固定三种设计枚举。`validatePayload`省略时默认按`{decisionRef}`校验，业务模块自定义载荷校验只改本模块描述符，不改公共引擎。
- execute/reconcile/cancel接收`{command,state,row,clients,skill,plugin,store,stamp,openLedger,getExecution}`。`clients`统一注入`{skill,plugin,mcp,agent,management}`五个HTTP客户端；`openLedger(name)`由公共引擎按模块命名空间托管打开与关闭，模块不自行维护SQLite关闭钩子；`init({dir,clients,openLedger,getExecution})`可选返回清理函数，在服务关闭时自动执行。由公共引擎维护执行ID、互斥、状态持久化和重启读取，模块不能另建第二套执行台账。跨系统访问使用HTTP，仓库服务不能直接import到业务模块。
- resources按kind登记`{list(ctx),detail?(ctx)}`（兼容旧函数简写），公共读取路由透传`{query,identity,clients,openLedger,getExecution}`，支持`/resources?kind=...`列表（含身份鉴权与分页）与`/resources/:kind/:resourceId`详情。
- catalogs按kind登记`{list?(ctx),detail?(ctx),versions?(ctx)}`，支持`/catalog`、`/catalog/:kind/:resourceId`与`/catalog/:kind/:resourceId/versions`；合法契约种类尚未实现时返回501 `UPSTREAM_UNSUPPORTED`。
- routes按HTTP方法与路径模板登记handle，支持静态路径与`:param`动态路径参数（如`/internal/v1/key-registrations/:registrationId/reveal`、`/internal/v1/executions/:executionId/account-consistency`），参数自动解码并注入`ctx.params`。形态冲突的动态路由在启动时按`DUPLICATE_ROUTE`拒绝；`capabilities`、`resources`、`catalog`、`downloads`及核心执行路由(`/executions`、`/executions/:id`、`/executions/:id/cancel`)为保留路径不可覆盖。
- 新业务目录只需公共负责人在app/modules.mjs组合一次；既有模块内新增动作/读取/路由/取消/对账实现只需改本模块目录，无需改平台公共代码。新增工单类型仍须两组先变更共享契约，不允许本模块私自扩大actions.json。
- reconcile支持挂在动作级（优先）或模块级，由所属模块提供产品任务只读查证，公共引擎按原命令所属动作调度；cancel支持挂在动作级，处理`POST /internal/v1/executions/:executionId/cancel`（终态自动返回409，未实现返回501）；不能重建已接单但结果未知的产品副作用。

同一注册索引同时服务`/capabilities`与执行分发，删除原来的download/install硬编码识别清单。业务实现的存在、完整性与目标部署验证是三个不同条件：

| 条件 | 返回状态与原因 | 执行分发 |
| --- | --- | --- |
| 无execute | unsupported / NO_HANDLER | 不调用产品 |
| 有草稿execute但ready:false | unsupported / IMPLEMENTATION_INCOMPLETE | 不调用草稿 |
| 有完整处理器、无匹配核验证据 | unverified / NO_DEPLOYMENT_EVIDENCE | 处理器已接线，管理端仍按原设计核验模板启用条件 |
| 完整处理器且匹配目标部署核验 | verified或证据给出的unverified/unsupported | 按既有工单/部署门槛执行 |

核验证据继续由`CAPABILITY_EVIDENCE_FILE`加载，唯一键为`ticketType+ticketTypeVersion+action+variant+workspaceId`，时间必须有效UTC且不能超前5秒；工作区不能借用通用或其他工作区证据。重复证据503/AMBIGUOUS_EVIDENCE。模块不能自行返回verified；不完整处理器即使给了verified证据也不会被提升。

## 当前实现事实

结构迁移不代表全部产品适配完成。现有Skill下载和插件安装处理器已迁移；无部署证明时仍为unverified。Dify智能体与密钥的六个已有处理草稿归入各自模块并设置ready:false：其中发布/下架没有实际产品操作，轮换仅创建新钥尚无旧钥撤销证明，其他动作也未覆盖本项目要求的完整身份/冻结依据/登记链路。这些草稿暂不自动执行，待对应模块按完整成功判据实现和验收后才能启用。

原有候选与目录中的演示数据保存在各模块queries/legacy-catalog.mjs与resources-*.mjs，迁移保留调用兼容，但不得作为生产数据、权限依据或部署核验证据。生产采集、正式身份及原子执行仍按能力组件开发分工逐项完成。原有executor与adapters导入路径保留薄转发，迁移新代码使用app启动及模块公开入口。

## 提交与验收

1. 本模块代码、README、测试和联调样例在自己的目录内完成；共享契约签名变化先对齐调用方；公共文件由公共负责人合入。
2. `npm.cmd run test:capability -- skills`运行指定模块测试；模块尚无测试时明确失败，不生成虚假的绿色验收。`npm.cmd run test:capability`运行当前能力侧公共与模块全部测试。
3. `npm.cmd run check:boundaries`同时检查管理与能力边界：禁止跨模块私有导入、模块反向依赖装配、平台反向依赖业务、能力导入管理实现、业务直接导入仓库、模块循环。
4. 合并前`npm.cmd run check`覆盖双侧边界、lint、构建、管理与能力全量接口回归。公共重构另回归实际Skill下载与回执。
5. 每个动作记录工单类型/版本/动作/分支/工作区、模块测试、模拟联调、真实部署证据。仅结构与模拟验收不能计入27种工单的整单完成数。
