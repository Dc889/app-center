### 2 人日常协作与验收门禁

1. **短分支独立推进**：每个独立任务开一条短分支，自测通过后立即合入主干；开发 B 仅在需改 `shared-ui/`、`app/`/`platform/` 或跨模块 `public.*` 签名时与开发 A 对齐，其余时间在自有 4 个目录内自主交付。
2. **禁止越界导入**：跨模块仅允许导入 `public.server.mjs` / `public.web.ts`；禁止模块反向依赖 `management/app/`，禁止浏览器导入服务端，禁止管理系统直接导入 `capability/`，禁止循环依赖。以上由 `npm.cmd run check:boundaries` 自动拦截。
3. **提交与合并前必跑命令**（在 `app-center/` 目录执行）：
   - 开发 B 每次提交前：`npm.cmd run check:boundaries`、`npm.cmd run test:module -- <当前模块名>`、`npm.cmd run test:browser -- <当前模块名>`。
   - 开发 A 改公共目录或合入主干前：全量 `npm.cmd run check`（边界 + lint + 构建 + 全量集成测试）。
4. **进度登记口径**：每完成一项，在对应模块 `README.md` 和本文档补齐测试命令与验收单号；基于模拟能力服务通过的仅标“管理端已完成”，与真实能力组件联调验收全部分支通过后才计入 `0 / 27` 整单完成数。
